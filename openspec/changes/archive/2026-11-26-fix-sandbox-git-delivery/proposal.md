# Proposal

## Why

Agents working in this repository's clone-mode `sbx` sandbox repeatedly mishandle Git delivery. Recent sessions show the same failures: attempts to push to GitHub (SSH port 22 is blocked and HTTPS has no credentials), creation of a fake bare repository at the host-side `/sandbox/<name>` path, "refreshing" from GitHub even though the host repository is far ahead of it, proliferating extra repository copies, and ending a session without ever confirming the user pulled the delivered branch. The generated sandbox guidance actively causes some of this: it claims the proxy handles GitHub authentication and tells the agent to push and open pull requests from inside the sandbox, which is false here. The actual contract is simpler and was verified during exploration: the host-side `sandbox-<name>` remote reads the sandbox's clone directly while the sandbox is up, so committing is delivery, and `/run/sandbox/source` is a live read-only view the agent can use to verify the host received the work.

## What Changes

- Rewrite the repo-controlled agent guidance for Git delivery so the only delivery route is a commit in the sandbox clone, retrieved on the host with `git fetch sandbox-<name>` and `git merge sandbox-<name>/<branch>`.
- Remove the GitHub story from agent guidance: no pushes, pull requests, `gh` login, or credential configuration from the sandbox unless the user explicitly asks for a GitHub push in the current session. Record that the observed push failures are expected and must not be retried or worked around.
- Document the two known traps explicitly: the host-side `/sandbox/<name>` remote path does not exist inside the sandbox and must never be created or pushed to; GitHub read access succeeds but is stale by design, so it must never be used to update or verify host state. The live host view is `/run/sandbox/source`.
- Forbid ghost-repo sprawl: work in `$WORKSPACE_DIR` (or an existing registered linked worktree); do not create extra clones, scratch copies, or new worktrees to "deliver" work.
- Replace the current "ask the user to pull" ending with a mandatory safe-to-drop verification: dirty files in every worktree, stashes, and host reachability of every branch tip via `git -C /run/sandbox/source merge-base --is-ancestor`. Every implementation report must end with an explicit "Safe to drop" or "NOT safe to drop" verdict and the exact host command when work is outstanding. If the user says they pulled, re-verify against the live mount before confirming.
- Update the repo docs that describe the handoff so they match the verified contract: `git fetch` + `git merge` (not only `git pull`), the live read-only mount, and the fact that GitHub is the user's channel, not the sandbox's.
- **Documentation and agent guidance only.** No hooks, helper scripts, remote renaming, new kits, new sandbox capabilities, or sandbox environment/tooling changes. The false GitHub-authentication block is generated by the `sbx` frontend outside this repository; the repo can only ensure its own guidance is correct, specific, and indexed for the agent.

## Capabilities

### New Capabilities

- `sandbox-git-delivery`: The sandbox agent guidance and repository documentation define a single host-fetch delivery contract, prohibit GitHub and fake-remote delivery paths, prevent redundant repository copies, and require a verified safe-to-drop verdict before work is reported complete.

### Modified Capabilities

(none — no existing capability's requirements change)

## Impact

- `sbx/kits/opencode-server/opencode-server-context.md` — primary agent-facing surface. It is staged at `/usr/share/sandbox/kit/opencode-server/opencode-server-context.md` and indexed in the generated `/home/agent/.config/opencode/AGENTS.md`; the delivery contract, GitHub prohibition, traps, and safe-to-drop protocol live here.
- `sbx/kits/opencode-server/opencode-server.yaml` — `description` text only, so the generated kit index signals that this context owns Git delivery. No capability, hook, or image change.
- `sbx/README.md` — Layout table and "Agent context and Git handoff" section: document the host fetch/merge contract, the live read-only mount, the GitHub prohibition, and the verification requirement.
- `sbxenv.yaml` — comment-only correction to the clone-mode retrieval command, replacing the bare `git pull` wording with the fetch/merge contract. No configuration change.
- `sbx/AGENT_WORKFLOW_PLAN.md` — status-note only: mark its original handoff instructions as superseded by the current contract. The historical body is preserved.
- `openspec/changes/fix-sandbox-git-delivery/` — proposal, spec delta, design, and tasks.
- The generated `sbx` frontend guidance block (including its "Git Authentication" section) is outside this repository and cannot be edited here. The repo-side guidance must explicitly override it; the design records this as a known residual risk.
- No application code, APIs, dependencies, or runtime behavior change. Guidance changes take effect only after the sandbox is recreated.
